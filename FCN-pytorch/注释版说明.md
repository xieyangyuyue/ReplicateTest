# FCN-pytorch 中文注释版说明

本仓库克隆自 [pochih/FCN-pytorch](https://github.com/pochih/FCN-pytorch)，
在**不改变代码逻辑**的前提下为每一行代码添加了中文注释；并针对
**Python 3.10 + PyTorch 2.x（cu121）+ 新版 pandas/scipy/torchvision** 完成了
兼容性适配，可直接在新环境运行。所有适配点均以 `【新环境适配】` 标注。

## 项目简介

FCN（全卷积网络）是语义分割的开山之作（CVPR 2015）。本项目基于 PyTorch 复现：
以 VGG16 为编码器提取特征，用转置卷积上采样恢复分辨率，并通过跳跃连接
融合浅层细节，实现端到端的逐像素分类。

## 运行流程（新环境：Python 3.10 + PyTorch 2.x cu121）

1. **装环境**（示例：micromamba + pip，torch ≥2.1 才有 cu121 轮子）：
   ```bash
   micromamba create -n seg python=3.10 -y
   micromamba activate seg
   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
   pip install numpy pandas pillow matplotlib
   ```
2. **下载数据集**：CamVid 或 Cityscapes，放到仓库根目录的 `CamVid/` 或 `CityScapes/` 下
3. **预处理**：`cd python && python CamVid_utils.py`（或 `Cityscapes_utils.py`），
   生成 `train.csv / val.csv` 与每像素类别索引的 `.npy` 标签（LUT 向量化，秒级完成）
4. **训练**：`python train.py CamVid`（或 `Cityscapes`）。
   注意工作目录必须在 `python/` 下（脚本用相对路径 `CamVid/`、`CityScapes/` 找数据）

## 新环境适配改动清单

以下修改均以 `【新环境适配】` 前缀标注在代码注释中。

### 1. 已移除/弃用 API 的替换（不改行为）

| 文件 | 原代码 | 改为 | 原因 |
| --- | --- | --- | --- |
| 两个 loader、两个 utils | `scipy.misc.imread(path, mode='RGB')` | `np.array(Image.open(path).convert('RGB'))` | scipy ≥1.10 彻底删除 `scipy.misc.imread`。注意 **imageio 是独立的第三方包**，不是 scipy 的子模块（`scipy.imageio` 不存在） |
| 两个 loader | `self.data.ix[idx, 0]` | `self.data.iloc[idx, 0]` | pandas ≥1.0 删除 `.ix` |
| train.py、fcn.py | `loss.data[0]` | `loss.item()` | 新版 PyTorch 标量张量不允许 `[0]` 索引（IndexError） |
| fcn.py | `exec("...models.vgg16(pretrained=True)...")` | `weights=VGG16_Weights.IMAGENET1K_V1`（旧版 torchvision 自动回退 `pretrained=True`） | torchvision ≥0.13 弃用 `pretrained` 参数；两种写法加载的是同一份权重 |
| fcn.py 自测代码 | `nn.functional.sigmoid` | `torch.sigmoid` | 已弃用 |

### 2. 补上原仓库缺失/写错的逻辑（不补会直接报错）

| 文件 | 问题 | 修复 |
| --- | --- | --- |
| CamVid_loader.py | **验证集形状不匹配**：验证图 720×960，高 720 不是 32 的倍数；网络 5 次下采样（720→22）再 5 次上采样只能回到 704，与 720 高的标签算损失/IoU 会报错。作者定义了 `val_h=704/val_w=960` 却没有写使用它们的代码 | 补上 `else` 分支：图像与标签**中心裁剪**到 704×960（上下各裁 8 行，不引入插值、不破坏标签边界）。Cityscapes（1024×2048）本身是 32 的倍数，此分支不生效；同时补齐了 Cityscapes 版 `new_h/new_w` 的非训练阶段初始化（原代码引用会 AttributeError） |
| train.py | `n_class` 硬编码 20：跑 CamVid（32 类）时模型输出 20 通道与 32 通道 one-hot 标签形状不匹配，损失报错 | 按命令行参数自动设置：CamVid→32、Cityscapes→20 |
| train.py | 不带参数运行直接 `IndexError` | 打印用法后退出 |

### 3. 预处理提速（结果与原实现逐像素一致，已用随机测试验证）

`CamVid_utils.py` / `Cityscapes_utils.py` 把逐像素双重 for 循环查表改为
256³ 颜色查找表（LUT）+ 整图花式索引：

- CamVid：每张 720×960（约 69 万像素）从数十秒 → 毫秒级；701 张从数小时 → 1 分钟内
- Cityscapes：每张 1024×2048（约 210 万像素）从 1~2 分钟 → 毫秒级；约 5000 张从数天 → 几分钟
- 查不到的颜色的兜底行为与原代码完全一致（CamVid 保持索引 0；Cityscapes 赋 19）
- 原始双重循环实现以注释形式保留在代码中备查

### 4. 已知无害警告（可忽略）

- `UserWarning: Detected call of lr_scheduler.step() before optimizer.step()`：
  故意保留原仓库"每轮开头调用 `scheduler.step()`"的顺序，以复现原学习率调度节奏
- `torch.save(fcn_model, model_path)` 保存的是整个模型对象（依赖 pickle）：
  PyTorch ≥2.6 加载时需 `torch.load(model_path, weights_only=False)`，
  且需在与保存时相同的代码环境下加载
